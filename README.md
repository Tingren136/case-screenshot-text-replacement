# 案例截图文字替换 Skill

把真实截图里的私人文字换成虚构内容，保留界面和展示效果。多张图共用一份替换对照表：整理前叫什么、后面建议改成什么、最终放进哪个项目，前后对应。

适合公众号、产品案例、作品集和操作前后对比。以真实截图为底稿，不凭空生成执行结果。

## 安装

把这个仓库链接发给支持图片编辑的 Codex，并说：

> 请安装这个仓库的 case-screenshot-text-replacement Skill，检查图片编辑能力是否可用：
> https://github.com/Tingren136/case-screenshot-text-replacement

安装方式：将本仓库 `skills/case-screenshot-text-replacement` 整个目录复制到当前 `CODEX_HOME/skills/` 下。已有同名版本先备份；不要把原图或私人替换表放进Skill目录。

需要宿主提供图片查看和编辑能力，优先使用内置生图工具及其 imagegen Skill。本仓库是工作流程说明，不捆绑图片模型、系统 imagegen Skill 或API密钥。仅安装这些文件不会给没有图片编辑能力的环境增加生图功能；缺少能力时先报告缺项，不擅自改用收费API或第三方服务。

## 使用

附上真实截图，然后说：

> 用 case-screenshot-text-replacement 处理这组案例截图。把私人聊天标题和项目名称换成虚构内容，保留真实布局、顺序和状态。先做第一张给我看；其余图片沿用同一份替换对照表，前后标题和项目要能对应。

如果现在只有第一张，先处理这一张。之后实际执行完成，再附上对应的反馈截图，让它继续处理；没有真实反馈图就等，不生成假报告补位。

## 怎么保持前后对应

例如，一组虚构展示内容可以这样安排：

| 截图阶段 | 同一条聊天的展示文字 |
| --- | --- |
| 整理前 | 接着上次的旅行攻略继续写，先看看交通 |
| 标题建议 | 周末旅行｜路线与交通安排 |
| 确认后 | 周末旅行｜路线与交通安排 |
| 项目归类 | 周末旅行 |

这只是对应关系示例。实际处理必须保留原图中的成功/失败、待确认/已执行、数量和分组关系，不能为了好看修改结果。两张图的行号相同，不代表是同一个对象；截断文字无法识别时先核对。

## 交付内容

- 另存后的图片，原图不覆盖。
- 简短的处理与检查说明。
- 本地私有替换对照表，供后续截图保持一致；不随分享图片公开。

图片编辑可能轻微重绘字体或界面细节。这种做法用于案例展示，不是逐像素保真编辑或严格匿名化；图片应标注“基于真实截图，展示文字已替换”，不作为原始执行证据。需要实色遮盖时可使用宿主已有的遮盖工具，本仓库不依赖安装其他私人Skill。

## 隐私

只提交Skill说明和全虚构示例。真实截图、私人对照表、提示词记录、账号配置与凭据都留在使用者自己的私有目录，不提交此仓库。不要把含密钥、设备码等凭据的原图直接送入图片编辑，先遮盖这些区域。

图片编辑会将选中的素材交给宿主图片模型处理，遵循该服务的数据与用量规则；这不是纯本地离线处理。工具不自动发布图片，也不操作真实业务系统来凑截图。
